# Вимоги до `current-2.md`

Цей файл є джерелом даних для профілю «Замовник 2». Сторінка читає його автоматично після оновлення файлу.

## 1. Заголовок і блоки

На початку звіту вкажіть заголовок через `#`. Основні функціональні блоки позначайте заголовками `##` або нумерованими заголовками `### 01. ...`. Назва блоку має бути окремим рядком.

Усередині блоку вказуйте сервіси заголовками `###` або `####`. Для кожної задачі важливо зберігати зв'язку «блок → сервіс → задача».

## 2. Поля задачі

Рекомендований формат задачі:

```md
- Назва задачі: Додати перевірку банківської виписки
  - Опис: Що саме потрібно зробити і який результат очікується.
  - Тип: баг
  - Статус: у роботі
  - Виконавці: @Denys_Shchyp, @batalova_k
  - Замовники: Андрій Борисенко, Інший замовник
  - Термін: 2 дні / 16 годин
  - Запланована дата: 12.08.2026
  - Джерело: Worksection 14531334
```

Підтримуються також короткі назви полів: `Виконавець`, `Замовник`, `Дедлайн`, `Планова дата виконання`, `Тривалість`, `Оцінка`.

### Обов'язкові поля

- `Назва задачі` — коротка назва або повний опис задачі.
- `Статус` — поточний стан.
- `Тип` — одне з: `баг`, `допрацювання`, `нова розробка`.
- `Виконавці` — один або кілька розробників через кому.
- `Замовники` — один або кілька замовників через кому.
- `Термін` — оцінка у днях і/або годинах.
- `Запланована дата` — дата завершення у форматі `ДД.ММ.РРРР`.
- `Джерело` — Worksection, GitHub, Outline або інше першоджерело.

Якщо значення ще невідоме, пишіть саме `інформація відсутня`. Не залишайте поле порожнім.

## 3. Правила для кількох учасників

В одному полі можна вказувати кілька виконавців або замовників через кому. Наприклад: `@Denys_Shchyp, @batalova_k`. Сторінка врахує кожну особу у фільтрі та підсумку.
